# ADR 0003 Chapter 13 integration decisions

1. Use a browser page and JSON endpoints served by one standard-library Python process. Traces: A1, A2, C.1 resident_interface, C.2 ticket_service, UC.1.WS and SIM.1. The prior built-in form called the service directly with AI off; the separate FastAPI interface did not make it an end-to-end REST path. The earlier optional Streamlit/FastAPI tools remain available. Update the tool allocations and the UC.1 front-end call.
2. Use the original ADR-0001 allocation for C.3, A1 and A7: LM Studio serves Meta Llama 3.1 8B Instruct. For a fresh installation, use the Q4_K_M GGUF with its published SHA-256. Chapter 13 verifies both the native model inventory and the identifier on actual chat responses. The independent runtime captures the installed server/runtime versions. Locality and resident and manager authority remain as designed.
3. Treat access permission and location as resident-owned source values. Only category and summary are requested from the model. Any plausible wrong category is editable. Missing access stays blank. T7.1, A1, C.3 intake_model and the Chapter 3 response-contract allocation should record the narrower interface.
4. Retain ADR-0002, two verified checkpoints, now merged into the course demonstration on 22 November. T6.D already records the decision. Update any earlier A7/SR.20 note describing a single copy or undecided retention.
5. Represent authentication with seeded, selectable demo accounts at C.0/A7/DC.2. Mark it simulated wherever the design implies institutional SSO. Optional photos are absent on this branch; identify this limitation on DI.1 and A1. SR.34/SN.12 grouped trends are deferred. The screen displays synthetic aggregate counts and durations and a configurable repeat window; the 7-day demonstration value is not an approved operational threshold.
