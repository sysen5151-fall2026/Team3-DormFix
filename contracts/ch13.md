# DormFix Chapter 13 interface contract

The Chapter 3 Data Contract and Model Response Contract are preserved in docs/baselines/ch03-spec.md. This as-built supplement describes the standard-library grading entry point. The historical demo branch did not supply a versioned Chapter 7 OpenAPI file.

| Boundary | Input and output | Absence, ownership and retry |
|---|---|---|
| IC1 browser to resident REST | POST /api/drafts with a JSON object containing description and optional text fields. Response contains draft, suggestions, missing_fields, manual_fallback and emergency_warning. | Demo actor header required. 401 for absent actor, 403 for inactive or wrong role. 400 for empty description or invalid JSON/types. Preparing a draft never creates a ticket. User initiates each retry. |
| IC2 adapter to local LLM | POST /v1/chat/completions with model alias, messages and response schema. Adapter extracts choices[0].message.content as JSON. The live schema requests category and summary. | Adapter ignores authority fields, validates optional field types, and keeps suggested access/location out of confirmed data. A missing model, timeout, bad body or service error returns a manual draft. The normal client wait setting is 30 seconds. The live acceptance run allows 180 seconds per request on CPU. Neither value is a service SLA. |
| IC3 confirmed draft to service/store | POST /api/tickets with confirmed=true, draft, UUID submission_key and optional advisory metadata. Response is a ticket ID and lifecycle state. | Resident owns meaning. Service validates all five required fields. Store serializes the lookup/insert and commits ticket plus first event before acknowledgement. Replay same key for same resident only. Errors preserve browser inputs. |
| IC4 authorized ticket to consumer | GET /api/tickets/{id}, header X-DormFix-Actor. Returns role-filtered record, next step, ordered history and timezone-aware event timestamps. Role workspaces use form POST for assignment/progress/completion/resolution. | Service enforces owner/assignment and authority. The resident alone normally accepts closure. An invalid handoff produces an error or denial. The UI refreshes on action, with no automatic repeat of a role command. |
| IC5 store to Administration | Aggregate-only counts, open age and closed duration separately in hours, repeat count and configured window in days. | Require active Administration identity. An empty cohort has null means. No individual rooms, contacts or records are sent. Recompute on page load. |
| IC6 IT to checkpoint storage | Authorized create returns generation and UTC time. Confirmed restore checks manifest digest, SQLite integrity, counts and alternatives in order. | Only active IT Support. A failed newest copy selects the previous verified copy; two bad copies leave live data intact. Operator owns confirmation, retry and recovery-gap review. |
